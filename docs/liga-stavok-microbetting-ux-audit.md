# UX-аудит микробеттинга — Лига Ставок

**Формат:** тестовое задание  
**Дата:** май 2026  
**Фокус:** только фича микробеттинга (in-play)

---

## 1. Что такое микробеттинг в контексте ЛС

Микробеттинг — ставки на ультракороткие события внутри матча: следующий угловой, ближайшие 2 минуты, следующее касание в зоне. Окно ставки — от 10 до 60 секунд. Это принципиально другой UX, чем обычный live-беттинг: **пользователь работает под временным давлением**, не может обдумывать решение и вернуться к нему.

---

## 2. Ключевые сценарии использования

| Сценарий | Контекст | Ожидание пользователя |
|---|---|---|
| Ставка за 15 сек | Смотрит трансляцию, видит момент | Нажать и получить подтверждение за 2–3 сек |
| Мониторинг котировок | Следит за движением odds | Чётко видеть направление изменений |
| Серийные ставки | Делает 5–10 ставок подряд | Не терять контекст матча, быстрый сброс |
| Ставка с одной руки | Едет в транспорте | Все действия доступны большим пальцем |

---

## 3. Обнаруженные UX-проблемы

### 3.1 Критические (блокируют цель пользователя)

**[P0] Нет визуального таймера окна ставки**  
Пользователь не знает, сколько времени осталось до закрытия рынка. Ставка «пропадает» без предупреждения — это воспринимается как баг, а не как закрытый рынок. Доверие падает.

**[P0] Подтверждение ставки неотличимо от ошибки**  
Toast-уведомление одинаково по виду для успеха и для отказа (рынок закрылся, ставка не принята). Под давлением времени пользователь не дочитывает текст — думает, что ставка прошла.

**[P0] Мерцание котировок без смыслового контекста**  
Odds перерисовываются жёстко — цифра просто меняется. Пользователь не понимает: котировка выросла или упала? Насколько быстро движется?

---

### 3.2 Серьёзные (ухудшают опыт)

**[P1] Размер тапа на кнопку ставки**  
Кнопка с коэффициентом ~44×36 pt при норме ~48×48 pt. В режиме торопливого взаимодействия процент промахов высок, особенно на узких экранах.

**[P1] Список микрорынков не приоритизирован**  
Все события показаны в одном списке без разбивки на «сейчас» / «скоро». Пользователь тратит время на поиск активного окна среди закрытых рынков.

**[P1] Живой счёт перекрывается при скролле**  
Контекст матча (счёт, минута) виден только в верхней части экрана и скрывается при скролле вниз к рынкам. Пользователь теряет привязку к игровой ситуации.

**[P1] Нет индикатора латентности**  
Между нажатием «Сделать ставку» и ответом сервера — пустота. 1–2 секунды ожидания без feedback'а заставляют нажимать повторно → двойная ставка.

---

### 3.3 Незначительные (снижают удовольствие)

**[P2] Нет истории микроставок в сессии**  
Пользователь не видит, сколько ставок уже сделал в этом матче. Нет ощущения «сессии».

**[P2] Цвета success/error близки при плохом освещении**  
Зелёный/красный для изменений котировок плохо считываются на ярком солнце. Нужен второй визуальный канал (иконка, анимация).

**[P2] Отсутствие haptic feedback**  
Принятие ставки — значимое событие, которое должно ощущаться физически. Сейчас — тишина.

---

## 4. Оценка по эвристикам Нильсена

| Эвристика | Оценка | Комментарий |
|---|---|---|
| Видимость статуса системы | ❌ 2/5 | Нет таймера, нет статуса отправки |
| Соответствие реальному миру | ✅ 4/5 | Термины понятны целевой аудитории |
| Контроль и свобода | ⚠️ 3/5 | Отмена ставки возможна, но неочевидна |
| Предотвращение ошибок | ❌ 2/5 | Нет защиты от случайного тапа/двойной ставки |
| Распознавание > запоминание | ⚠️ 3/5 | Контекст матча пропадает при скролле |
| Гибкость и эффективность | ⚠️ 3/5 | Нет быстрых пресетов суммы для серийных ставок |
| Эстетика и минимализм | ⚠️ 3/5 | Много элементов одновременно, нет иерархии |
| Диагностика ошибок | ❌ 2/5 | Сообщения об ошибках технические |

## 5. Идеи по анимации

### 5.1 Таймер закрытия рынка

**Концепция:** Кольцевой прогресс-бар вокруг кнопки «Сделать ставку», который сходит на нет за последние 10 секунд окна. На последних 3 секундах — пульсация кнопки.

```
Кнопка [--- ставка ---]
         ^ring progress
```

**Технически:** `stroke-dashoffset` на SVG circle + CSS transition. На 3 сек → добавить `animate-pulse` класс.  
**Зачем:** Убирает тревогу от неизвестности. Пользователь не гадает — видит окно.

---

### 5.2 Движение котировок (Odds momentum)

**Концепция:** При изменении коэффициента — не просто перерисовка, а «переворот» числа (flip animation) с цветовым trail: рост → зелёный fade, падение → красный fade. Если odds изменилась больше чем на 20% за последние 5 сек — добавить micro-иконку тренда (▲▼).

```
[ 2.45 ] → flip → [ 2.61 ] + зелёный след + ▲
```

**Технически:** CSS `rotateX(90deg)` → смена числа → `rotateX(0)` + background-color transition.  
**Зачем:** Пользователь мгновенно считывает направление без чтения чисел. Особенно важно при серийных ставках.

---

### 5.3 Подтверждение ставки — «Bet locked»

**Концепция:** При принятии ставки — иконка замка «защёлкивается» (spring-анимация scale 0 → 1.2 → 1.0), карточка рынка кратко подсвечивается зелёным border'ом и уходит в минимизированное состояние. Haptic — тяжёлый удар.

**Зачем:** Создаёт ощущение завершённости действия. Пользователь уверен, что ставка принята, и переключается на следующую.

---

### 5.4 Обновление счёта — «Goal moment»

**Концепция:** Когда меняется счёт матча, score-блок наверху делает краткий scale punch (1.0 → 1.15 → 1.0, 200мс) + цифра «отпрыгивает» вверх. Фон блока мигает цветом команды, которая забила.

**Зачем:** Пользователь следит за матчем через приложение — нужен эмоциональный feedback на ключевые события. Это также момент для новой микроставки.

---

### 5.5 Список рынков — «Market opens»

**Концепция:** Когда открывается новое микро-окно (новый рынок становится активным), карточка появляется сверху списка с анимацией slide-down + краткий border-glow эффект в течение 1.5 сек. Закрытые рынки плавно «сдуваются» (high → 0, opacity 1 → 0.3).

```
[НОВЫЙ] ↕ slide in + glow
[active market]
[closed]  ← dimmed
```

**Зачем:** Пользователь моментально видит новое окно без сканирования списка.

---

### 5.6 Skeleton + latency feedback

**Концепция:** Сразу после нажатия «Сделать ставку» — кнопка переходит в loading-состояние: три точки с wave-анимацией. Если ответ не пришёл за 2 сек — появляется подсказка «Обрабатываем...». Кнопка блокируется от повторного нажатия.

**Зачем:** Устраняет двойные ставки и снижает тревогу ожидания.

## 7. Итог

Микробеттинг — это **стресс-тест UX**: скорость, точность и доверие важнее красоты. Главные провалы текущего решения — в базовом коммуникации статуса системы (таймер, подтверждение, обработка). Анимации здесь — не украшение, а **функциональный инструмент снижения когнитивной нагрузки**: odds flip убирает необходимость читать цифры, таймер снимает тревогу, bet locked даёт уверенность.

Приоритет фиксов: коммуникация статуса → предотвращение ошибок → информационная иерархия → анимационный polish.
